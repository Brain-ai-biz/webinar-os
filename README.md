# Webinar-OS · וובינר חי שלם, ב-10 שלבים, עד הדף באוויר

הפקת וובינר היא 15 משימות קטנות על 8 כלים: מחקר, מצגת, תסריט, דף הרשמה, דף תודה, קבוצה, מיילים, וואטסאפים, זום. כל אחת "קטנה", וביחד זה שבוע, ותמיד שוכחים משהו.

**Webinar-OS** הוא סקיל ל-Claude Code. כותבים `/webinar-os`, עונים על 8 שאלות תוכן (ועוד 3 קצרות על הטון; בשלבים 2 ו-3 יש עוד שאלת בחירה קצרה אחת בכל שלב: מצגת HTML או מתווה, ונרשמים לגיליון או כפתור לקבוצה), ו-Claude מוביל/ה אותך ב-10 שלבים קבועים, באותו סדר, כל שלב מסתיים בקבצים מוכנים ובהוראה ידנית של דקה-שתיים. ארבעה אישורים בדרך (קופי הדף, התזכורות, העיצוב, כיווני המסר). **הזרימה נגמרת בכתובת חיה**: בשלב 9 הדף עולה לאוויר, ואת/ה מקבל/ת לינק שאפשר להדביק בפרסום. כל הריצה: כ-75-110 דקות, מתוכן 3-5 דקות שקטות במחקר של שלב 1 (ב-Windows עד 5) ו-8-12 דקות שקטות בשלב 2. זה תקין, ככה זה נמדד. אם עברו 15 דקות בלי כלום, זה הזמן לבדוק. בזמן הריצה Claude יבקש אישור לפני כל הרצת סקריפט או פתיחת קובץ; לוחצים Yes (או "Yes, don't ask again" לפקודה הזו). בלי מפתחות API ובלי חיבורים. שאלות העיצוב נשאלות רק בשלב 8, אחרי שכבר יש מה לראות. עובד אצל כולם, ב-Mac וב-Windows, בחינם.

## האם וובינר מתאים לעסק שלך? בדיקה של דקה

לפני שמתקינים משהו, שאלה אחת ישרה. תאר/י לעצמך שעה מול חמישים אנשים שמתעניינים בתחום שלך. בסוף השעה, לפחות חמישה או עשרה מהם היו רוצים להמשיך איתך למשהו: ללמוד, להתייעץ, לקנות, לעבוד יחד. אם התשובה כן, וובינר הוא כנראה הכלי הכי חזק שיש לך, כי הוא נותן לך את השעה הזאת בלי אולם ובלי תקציב.

אם התשובה לא, שווה לעצור ולשאול למה, כי בדרך כלל זו אחת מהשלוש:

- **אין לך מה למכור אחרי.** אפשר להריץ וובינר בשביל רשימה וקהל, אבל אז מודדים אותו במספר הנרשמים ולא בהכנסות, ומחליטים את זה מראש.
- **המוצר נקנה בלי שיחה.** אם אנשים קונים ממך בלחיצה, שעה של הסבר לא תוסיף, ועדיף תוכן קצר.
- **אין לך איך להביא חמישים אנשים.** רשימה, קהילה, עוקבים או תקציב פרסום. הערכה בונה את המשפך כולו, אבל היא לא מביאה קהל. זה החלק שלך.

הערכה לא תגיד לך שוובינר נכון לך. היא תבנה אותו מצוין ברגע שהחלטת.

## התקנה ב-3 צעדים

**לפני שמתחילים:** צריך Claude Code מותקן ומחובר לחשבון. אין? נכנסים ל-claude.com/code, מתקינים לפי ההוראות שם, פותחים טרמינל חדש ומריצים `claude` פעם אחת כדי להתחבר. רק אחרי שזה עובד ממשיכים לצעד 1.

1. יוצרים (או בוחרים) תיקיית פרויקט שבה תעבדו, למשל תיקייה ריקה בשם `webinars` בתוך Documents.
2. מורידים את הזיפ ופותחים אותו **בתוך התיקייה הזו**. מקבלים שם תיקייה בשם `webinar-os`. (חשוב: Claude Code קורא רק קבצים בתוך תיקיית הפרויקט; זיפ שנשאר ב"הורדות" הוא לא רואה.)
3. פותחים טרמינל (Mac: Terminal, Windows: PowerShell), מקלידים `cd ` ואז גוררים את תיקיית הפרויקט לחלון, Enter, ואז מקלידים `claude` ו-Enter. (הטרמינל עונה `claude: command not found` או `'claude' is not recognized`? Claude Code לא מותקן, או שהטרמינל נפתח לפני ההתקנה: ראו "לפני שמתחילים" למעלה, ואת `skills/webinar-os/reference/troubleshoot.md` שורה 0.) כש-Claude Code נפתח, מדביקים לו את הפרומפט הזה:

```
התקן/י את הסקיל webinar-os מהתיקייה webinar-os (בתוך הפרויקט) לפי הקובץ INSTALL.md שבתוכה. בסוף אמור/י לי שהכל תקין ומה הפקודה להפעלה.
```

לא בטוח/ה בנתיב? גורר/ת את התיקייה `webinar-os` לחלון הטרמינל והנתיב המלא יודבק לבד.

בדרך Claude Code יבקש כמה בקשות הרשאה (העתקה לתיקייה `.claude/`, הרצת Python, יצירת תיקייה): מאשרים כל אחת, זו הגנה של Claude Code, לא תקלה. מכאן Claude מעתיק/ה את הסקיל ל-`.claude/skills/webinar-os/` בפרויקט, מריץ/ה בדיקה של 5 שניות, ומחזיר/ה "מוכן". מאז: `/webinar-os` בשיחה חדשה, וזה מתחיל מיד בשאלה הראשונה.

## שאלות שנשאלו, ותשובות קצרות

**מאיפה מגיעה התיקייה ואיפה שמים אותה.** מקבלים קובץ זיפ אחד. פותחים אותו בתוך תיקיית הפרויקט שבחרת (ראו "התקנה ב-3 צעדים"), כך שנוצרת בתוכה תיקייה בשם `webinar-os`. Claude Code רואה רק קבצים שנמצאים בתוך תיקיית הפרויקט שממנה הוא הופעל, אז זיפ שנשאר בתיקיית ההורדות פשוט לא קיים בשבילו.

**כמה זה עולה.** הרצה מלאה היא שיחה ארוכה עם Claude, והכבדות ביותר הן שלב 2 (המצגת) ושלב 8 (העיצוב). בחשבון Claude בתשלום זה נספר מול מכסת השימוש הרגילה שלך, וריצה מלאה נכנסת בדרך כלל בתוך חלון שימוש אחד; אם נגמרה המכסה באמצע, ממשיכים אחר כך עם `/webinar-os המשך` בלי לאבד כלום. אין צורך במפתח API של Claude ואין תשלום נוסף לערכה. מפתח של OpenAI נדרש רק בשלב 10, לייצור תמונות הקריאייטיבים, והוא מחויב בנפרד לפי השימוש. אין מפתח? כל הטקסטים עדיין נכתבים ורק התמונות מדולגות.

**על מה זה עובד.** הערכה נבנתה ל-Claude Code, ב-Mac וב-Windows, ונבדקה בשניהם. כלים אחרים (הצ'אט של Claude, ChatGPT וכדומה) הם best-effort בלבד, בלי אחריות ובלי הסקריפטים, עם 7 פרומפטים מוכנים ב-`skills/webinar-os/reference/other-tools.md`.

**יש לך כבר מערכת דיוור?** קרא/י את `skills/webinar-os/reference/advanced.md` סעיף 5 לפני שלב 3, לא אחריו. שם כתוב איך מחברים את הטופס ישירות למערכת שלך במקום לגיליון, וזו החלטה שנוח לקבל לפני שהדף נבנה.

**כמה נרשמים/ות מותר לי, וכמה זה עולה.** ההרשמות נשמרות באתר שלך ב-Netlify, והן **חינם ובלי הגבלה** במסלול החינמי של היום. לא משנה אם נרשמו 40 או 4,000. מה שכן מוגבל שם הוא 300 קרדיטים בחודש, וכל העלאה של הדף לאוויר עולה 15 מהם, כלומר כ-20 העלאות בחודש. לכן בודקים את הדף במחשב ומעלים כשהוא מוכן, במקום להעלות אחרי כל תיקון מילה. יש לך חשבון Netlify ותיק מהתוכנית החינמית הישנה? שם דווקא יש תקרה של 100 הרשמות לחודש, ומעבר למסלול הקרדיטים ב-Billing מסיר אותה.

**הדף עולה לאוויר בשלב 9.** עד אז הוא קובץ במחשב שלך, ואפשר לפתוח אותו בדפדפן ולראות אותו בדיוק כמו שהוא יהיה. אין כתובת חיה ואף אחד לא יכול להיכנס אליו לפני שלב 9. זה בכוונה: קודם מסיימים, אחר כך מפרסמים.

**שאלות העיצוב מגיעות בשלב 8.** לא בהתחלה, וגם זה בכוונה. עד שם הכל בנוי על מערכת עיצוב אחת שנראית טוב מהרגע הראשון, ובשלב 8 בוחרים כיוון מול תצוגות אמיתיות שאפשר לפתוח, במקום לדמיין צבע לפני שיש מה לצבוע.

**כל הוובינרים גרים בתיקייה אחת.** תיקיית הפרויקט שבחרת בהתקנה היא הבית: כל שידור מקבל תיקייה משלו תחת `outputs/webinars/`, וכולם יושבים זה לצד זה. הפעל/י את Claude Code תמיד מאותה תיקייה. פתיחת תיקייה חדשה למחר פירושה מערכת שלא מכירה אותך: בלי הסקיל המותקן, בלי הקונפיג, בלי הקול שהגדרת ובלי הוובינר הקודם להמשיך ממנו.

**מדיניות פרטיות: מה צריך להיות בה.** הסקיל שואל על לינק. אין? הוא אומר שצריך אחד לפני שהדף עולה לאוויר, ובונה בכל מקרה. הוא לא מנסח טקסט משפטי ולא מתיימר לתת ייעוץ משפטי. הרשימה הבאה היא מה שדף נחיתה שאוסף פרטים בישראל צריך שיהיה מכוסה, והיא מה שלוקחים לעורך/ת דין כדי שינסח/תנסח: מי אוספ/ת את המידע (שם מלא של העסק ופרטי יצירת קשר); אילו פרטים נאספים בפועל (שם, טלפון, מייל, וגם נתוני גלישה כמו מקור ההגעה וכתובת IP); לשם מה הם נאספים (שליחת הלינק לשידור, תזכורות, ודיוור המשך אם יש); על סמך מה, כלומר ההסכמה שניתנה בתיבת הסימון; למי המידע מועבר (מערכת הדיוור, שירות האחסון של הדף, כלי מדידה ופרסום, וכל אלה לרוב מחוץ לישראל); כמה זמן הוא נשמר; מה הזכויות של מי שנרשם/ה (לעיין, לתקן, למחוק ולבקש הסרה, וכיצד בדיוק); איך מסירים את עצמך מרשימת הדיוור; שימוש בעוגיות וכלי מעקב, אם יש; ולמי פונים בשאלה או בבקשה, בכתובת מייל שעונה. בנוסף לזה: קישור למדיניות בפוטר של כל דף, ותיבת הסכמה אחת שלא מסומנת מראש. אם את/ה עובד/ת גם מול קהל באירופה, יש שם דרישות נוספות, וזו בדיוק שאלה לעורך/ת דין.
