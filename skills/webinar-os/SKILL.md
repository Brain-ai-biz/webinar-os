# /webinar-os - מכונת הפקת וובינרים בפקודה אחת

פקודה אחת שמפיקה משפך וובינר LIVE שלם (15 רכיבים) לכל וובינר, **מותאם לכלים שיש למשתמש/ת**. הכל פרמטרי: נושא, זווית, תאריך, הצעה, קהל, CTA, מיתוג, כלים. כלום לא מקודד קשיח.

**דוקטרינה (לא מתפשרים):**
- כמה שיותר פשוט, לגמרי פרמטרי. `config.json` הוא מקור האמת היחיד לריצה.
- **בדיוק 2 עצירות אישור אנושיות:** (1) הקופי, (2) הקריאייטיבים. כל השאר רץ אוטומטית.
- עברית, פנייה דו-מגדרית (יחיד/ה קודם, למשל "בעל/ת עסק"), בלי קו מפריד ארוך (em dash) - רק מקף רגיל.
- לעולם לא ממציאים נתונים. רק עובדות שהמחקר אימת, עם מקור ולינק.
- **כלל הכלים:** לכל רכיב יש מסלול אוטומטי (אם יש כלי מחובר) ומסלול ידני (תוצר מוכן להדבקה + הוראות של 2 דקות). לא נתקעים על מה שאין, לא מזייפים פריסה. בסוף מדווחים ליד כל רכיב באיזה מסלול הוא נבנה.
- **היעד המינימלי:** גם מי שיש לו/ה רק Claude Code ואפס חיבורים מסיים/ת עם: 2 דפי HTML, מצגת, 3 מיילים, 4 הודעות וואטסאפ, 5 קריאייטיבים, לוח שילוח, ולכידת לידים דרך Google Form. הכל כקבצים ב-`outputs/webinars/<slug>/`.

## שלב 0 - שאלות תוכן (AskUserQuestion, 8 שאלות)

מקבצים לכמה קריאות AskUserQuestion בודדות, עם ברירות מחדל חכמות כדי שאפשר יהיה לאשר בקליק:

1. **נושא הוובינר** (→ `topic`)
2. **הזווית / ההוק** - עמוד השדרה הרגשי. מציעים 2-3 זוויות + אפשרות חופשית (→ `angle`, `big_idea`)
3. **תאריך ושעה** (→ `date_he`, `date_iso`, `time`, `event_iso`)
4. **מה מוכרים בקצה** - קורס / תוכנית / שיחת ייעוץ / כלום (→ `offer`; כלום = `no_promise: true`)
5. **קהל היעד** (→ `audience`)
6. **מטרת המשפך** - להירשם ולהגיע / למכור מוצר / לקבוע שיחה (→ `cta_goal`)
7. **slug** - שם קצר באנגלית kebab-case. מציעים אחד מהנושא (→ `slug`)
8. **המצגת** - ברירת מחדל: LIVE, בערך 40 שקפים, בלי דמו חי, צילומי מסך במקום (→ `deck`)

שאלת מיתוג אחת בסוף: שם המותג, צבע הדגשה אחד (hex), פונט (ברירת מחדל Assistant מ-Google Fonts), לוגו ותמונה אם יש, כתובת מדיניות הפרטיות (→ `brand_name`, `brand`, `privacy_url`, `hero_photo`). אין מדיניות פרטיות? אומרים שחובה לפני עלייה לאוויר ומציעים לנסח דף בסיסי כרכיב נוסף.

כותבים את התשובות ל-`outputs/webinars/<slug>/config.json` לפי `config.template.json`.

## שלב 0.5 - ראיון התאמה (מה מחובר אצלך)

קוראים את `reference/setup-interview.md` ושואלים 6 שאלות קצרות: אחסון לדפים / מערכת דיוור / וואטסאפ (API או ידני) / זום או אחר / קיצור לינקים / כלי תמונות ומצגות. **לפני ששואלים, בודקים לבד מה קיים**: MCP מחוברים, `.env`, סקריפטים קיימים, Composio אם מותקן. כל תשובה נשמרת ב-`config.integrations` וקובעת לכל רכיב מסלול אוטומטי או ידני.

מי שעונה "לא יודע/ת" על הכל מקבל/ת את חבילת האפס: Netlify Drop + Google Form + קבוצת וואטסאפ ידנית + Bitly + זום בממשק. זה עובד תמיד.

## שלב 1 - מחקר

אם הנושא מרוויח מנתונים קשים (כמעט תמיד): מחפשים ברשת סטטיסטיקות ודוגמאות מאומתות ממקורות מהימנים (מחקרים, דוחות של חברות ייעוץ גדולות, כתבות מקור). כלל ברזל: כל נתון חייב מקור עם לינק ושנה. נתון בלי מקור לא נכנס. מקור משני מסומן "הערכת שוק".

הממצאים המזוקקים נכתבים ל-`config.json → research_brief` ומזינים גם את המצגת (שקפי נתון גדולים) וגם את הקופי.

## שלב 2 - קופי מלא → **עצירת אישור מס' 1**

קוראים את `reference/copy-spec.md`. אם אין למשתמש/ת קובץ קול, שואלים 3 שאלות טון קצרות (שם). כותבים את כל קופי המשפך מתוך הקונפיג ושומרים ל-`outputs/webinars/<slug>/copy.json`:

- **דף נחיתה**: טיקר, הוק (הזווית, לא הנושא), תת-כותרת עם הבטחה, פסקת כאב, "מה תלמד/י בלייב" 4-5 בולטים, פרטי אירוע, גשר להצעה, טופס.
- **דף תודה**: אישור חם, לינק לקבוצת הוואטסאפ, 3 צעדים, שורת יומן.
- **3 מיילים**: ברוכים הבאים (מיד) / מחר בשעה X (יום לפני) / עוד שעה.
- **4 הודעות וואטסאפ**: מחר / היום / עוד שעה / התחלנו. קצרות: 2-4 שורות, לינק בסוף.
- **5 קריאייטיבים**: מחר / מחר ב-HH / היום ב-HH / עוד שעה / התחלנו. שורת פאנץ' + שורת משנה לכל אחד.

**עוצרים. מציגים בצ'אט**: כותרת ותת-כותרת הנחיתה, 3 המיילים, 4 הוואטסאפים, 5 שורות הפאנץ'. מתקנים לפי הערות עד אישור. תיקון נקודתי = מייצרים מחדש רק את הסעיף שביקשו וממזגים ל-copy.json.

> עצירה 1 מתוך 2. לא בונים ולא פורסים כלום לפני אישור.

## שלב 3 - המצגת

קוראים את `reference/deck-structure.md`. בונים דק LIVE לפי 14 המערכות מתוך `topic`, `angle`, `big_idea`, `research_brief` (נתונים מאומתים → שקפי big-stat) וגשר ההצעה.

- **ברירת מחדל**: מעתיקים את `templates/deck-basic.html` ל-`outputs/webinars/<slug>/deck.html`, ממלאים את השקפים (8 תבניות: title / big-stat / three-columns / bullets / quote / screenshot / section / cta), מחליפים את 5 משתני המיתוג ב-`:root`. פותחים בדפדפן, `?print` + Cmd/Ctrl+P = PDF.
- **הכלי של המשתמש/ת** (Google Slides / Canva / PowerPoint): מייצרים `deck-outline.md` עם שקף-שקף (כותרת, טקסט, תבנית, הערת דובר) להדבקה.
- בנוסף: `presenter-script.md` - תסריט הגשה מלא, מה אומרים על כל שקף.

## שלב 4 - קריאייטיבים → **עצירת אישור מס' 2**

`scripts/render_pages.py` (שלב 5) מייצר 5 קבצי HTML ב-`out/creatives/` מתוך `templates/creative.html` והטקסטים המאושרים. מריצים אותו כבר עכשיו כדי לראות את הקריאייטיבים:

```bash
python3 <skill-dir>/scripts/render_pages.py --config outputs/webinars/<slug>/config.json
```

מצלמים ל-PNG: אם Playwright קיים, מצלמים אוטומטית (1080×1080, ו-`?story` ל-1080×1920). אם לא, ההוראות בראש `creative.html` (צילום מסך מכלי הפיתוח בדפדפן). אם למשתמש/ת יש כלי תמונות מחובר (Canva MCP, מודל תמונות), מציעים אותו כחלופה.

**עוצרים. מציגים את 5 הקריאייטיבים** (פותחים את הקבצים). מתקנים עד אישור.

> עצירה 2 מתוך 2. אחריה הכל אוטומטי.

## שלב 5 - בנייה לפי מסלול (אוטומטי, מקצה לקצה)

קוראים את `reference/components.md` ועוברים על 15 הרכיבים לפי הסדר. לכל רכיב: `config.integrations` קובע מסלול אוטומטי או ידני. למסלולים הידניים, ההוראות המדויקות ב-`reference/manual-paths.md`.

הסדר החשוב:
1. **קבוצת וואטסאפ + לינק מקוצר** קודם (הלינק נכנס למיילים, לדף התודה ולקריאייטיבים).
2. **זום / שידור** → `broadcast_link`.
3. **לכידת לידים** (Google Form / endpoint / טופס דיוור) → `form_action` + `form_fields` או `capture_endpoint`.
4. **דפים**: `render_pages.py` → `out/index.html` + `out/thank-you/index.html`. פריסה לפי `integrations.hosting`. אחרי הפריסה: מעדכנים `page_url`.
5. **מיילים + וואטסאפ**: תזמון במערכת אם מחוברת, אחרת קובץ לוח שילוח לפי `reference/schedule.md`.

**חובה על כל טופס לידים:** תיבת הסכמה אחת (מדיניות פרטיות + תנאי שימוש + עדכונים), חובה לסימון, עם לינק ל-`privacy_url`. `consent-block.html` מוזרק אוטומטית; לא מוחקים אותו.

**בדיקת זר/ה לפני שמכריזים "מוכן":** נרשמים בדף החי עם מייל בדיקה → השורה מופיעה (גיליון / מערכת דיוור) → דף התודה נפתח → הכפתור מוביל לקבוצה. מוחקים את רשומת הבדיקה.

בסוף מעדכנים ב-`config.json` את כל הלינקים שנוצרו.

## שלב 6 - ניתוח אחרי הוובינר

## כללי ברזל
- לא שומרים מפתחות API בקבצים. סודות רק ב-`.env` שלא עולה לגיט.
- לא ממציאים נתונים. לא מזייפים פריסה: כלי לא מחובר = מסלול ידני, ואומרים את זה.
- שתי עצירות האישור קדושות. כל מה שביניהן ואחריהן אוטומטי.
- כל ריצה חיה ב-`outputs/webinars/<slug>/`: מבודדת וניתנת לשחזור.
- Claude Code הוא המסלול הנתמך. כל דבר אחר (Claude.ai, ChatGPT) הוא best-effort דרך `reference/other-tools.md`.
