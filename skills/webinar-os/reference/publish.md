## 0. כללי השפה בשלב הזה (חובה, גם בצ'אט)

השלב הזה מלא שמות לועזיים ובהוראות טכניות, וכאן בדיוק נשברים כללי השפה. הם חלים על **כל שורה שנכתבת למשתמש/ת**, לא רק על הקבצים:

1. **עברית.**
2. **פנייה דו-מגדרית, יחיד/ה קודם:** "תוכל/י", "הדבק/י", "פתח/י", "לחץ/י". **לא** "תדביקי" ולא "תדביק" לבד. `config.voice.address = singular` פירושו **יחיד/ה דו-מגדרי/ת**, לא מגדר אחד.
3. **בלי קו מפריד ארוך (em dash, U+2014) ובלי קו באורך בינוני (en dash, U+2013)**, גם לא בצ'אט. מקף רגיל, נקודתיים, או שתי שורות.
4. **בלי מילה לועזית בתחילת שורה**, גם לא בפריט ברשימה ממוספרת ולא בכותרת מודגשת.
5. **גם שורות ההסבר הקצרות לפני הרצת פקודה נכתבות בעברית** ("עכשיו שלב 9, קורא/ת את קובץ ההעלאה"), לא באנגלית.

שלוש דוגמאות לתיקון, מריצה אמיתית שנכשלה:

| נכשל | תקין |
|---|---|
| `**(א) Netlify דרך Claude - מומלץ:**` | `**(א) העלאה דרך Netlify עם Claude (מומלץ):**` |
| `כשיש לך את הכתובת [קו ארוך] הדביקי אותה כאן` | `כשיש לך את הכתובת, הדבק/י אותה כאן` |
| `Claim site כדי שהדף יישאר` | `לוחצים על Claim site כדי שהדף יישאר` |

ועוד כלל אחד לשלב הזה: **לא מציעים ביוזמתנו לדחות את ההעלאה.** אם המשתמש/ת ביקש/ה לדחות, מסמנים את שלב 9 כנדחה ב-`state.json` (מערך `deferred`), אומרים בשורה אחת איפה הלידים ייאספו כשהדף יעלה, ורושמים את זה ב"מה נשאר לך לעשות". יוזמה לדחות באה רק מהמשתמש/ת.

## 2. מסלול א: Netlify דרך Claude (מומלץ)

### הטוקן, בארבעה צעדים

1. נכנסים ל-app.netlify.com ופותחים חשבון חינם (אפשר עם חשבון Google).
2. לוחצים על התמונה בפינה ← **User settings**.
3. בתפריט הצדדי: **Applications** ← בקטע **Personal access tokens** לוחצים **New access token**.
4. נותנים שם (למשל `webinar-os`), לוחצים **Generate token**, ומעתיקים את המחרוזת. **היא מוצגת פעם אחת בלבד.**

מדביקים אותה בצ'אט, ואנחנו שומרים אותה ל-`.env` ואומרים שורה אחת יבשה: "נשמר ל-.env". זהו. **בלי אזהרות אבטחה, בלי "זה מסוכן", בלי להציע להחליף טוקן.** מי שכן רוצה לבטל טוקן ימצא **Revoke** באותו מסך שבו יצר אותו.

### ההעלאה

```
python3 <skill-dir>/scripts/deploy_netlify.py --config outputs/webinars/<slug>/config.json --token <הטוקן>
```

שם יפה לכתובת (רשות): מוסיפים `--site-name <slug>`. בלי זה נלקח `config.slug`.

הסקריפט (ספרייה סטנדרטית בלבד, בלי התקנות):

1. בודק שהטוקן תקין, ושומר אותו ל-`.env` כדי שההרצות הבאות לא יצטרכו אותו.
2. אורז את התיקייה `landing` בזיכרון לקובץ zip (בלי קבצים מוסתרים).
3. אין `config.netlify_site_id`? יוצר אתר חדש ומנסה לתפוס לו את השם המבוקש. יש? מעלה לאותו אתר.
4. **מדליק זיהוי טפסים על האתר החדש.** באתר חדש ב-Netlify הזיהוי כבוי כברירת מחדל, וכשהוא כבוי שליחה מהטופס מקבלת 404 וכל הרשמה נעלמת בשקט. הסקריפט שולח `PATCH` שמכבה את `ignore_html_forms`, ומעלה שוב כדי שהטופס ייקלט.
5. מחכה עד שהפריסה במצב `ready`.
6. כותב `config.page_url` ו-`config.netlify_site_id` לקונפיג.
7. מרנדר את הדפים שוב, כדי שהכתובת החיה תיכנס ל-`og:url` ול-`canonical`, ומעלה עוד פעם. לכן בהרצה הראשונה יש כמה העלאות רצופות; זה תקין.
8. מדפיס את הכתובת החיה, את כתובת דף התודה, ואת הפקודה שמציגה את הנרשמים/ות.

לראות את הנרשמים/ות (מצב א, `netlify_form` בקונפיג):

```
python3 <skill-dir>/scripts/deploy_netlify.py --config outputs/webinars/<slug>/config.json --submissions
```

ומי שנעלם/ה: אותה פקודה עם `--spam`, ההסגר של Netlify.

לראות מה היה נשלח בלי לשלוח כלום ובלי טוקן:

```
python3 <skill-dir>/scripts/deploy_netlify.py --config outputs/webinars/<slug>/config.json --dry-run
```

לבדוק רק שהטוקן עובד: `--token <הטוקן> --check`.

## 3. מסלול ב: Netlify Drop ידני, בלי חשבון

1. נכנסים ל-app.netlify.com/drop וגוררים את **כל התיקייה `landing`** (לא רק `index.html`; דף התודה הוא נתיב יחסי `thank-you/`).
2. מקבלים כתובת מסוג `random-name.netlify.app`. זה `config.page_url`, וכותבים אותה לקונפיג ביד. הכתובת עובדת מיד, כולל `/thank-you/`.
3. הדף יישאר לצמיתות רק אם נרשמים (חינם) ולוחצים **Claim site**. בלי זה הוא זמני. שם יפה: Site settings ← Change site name.
   **במצב א (Netlify Forms) יש כאן צעד ידני אחד**, כי אף סקריפט לא נגע באתר הזה: Site configuration ← Forms ← **Enable form detection**, ואז גוררים את התיקייה שוב. בלי זה השליחה מהדף מקבלת 404 ואף הרשמה לא נשמרת.
4. עדכון: מרנדרים שוב וגוררים שוב את `landing` על אותו אתר (Deploys ← drag).

כדאי לומר בשורה מה המסלול הזה מוותר עליו: אין `netlify_site_id` בקונפיג, ולכן כל עדכון עתידי הוא גרירה ידנית ולא פקודה.

## 4. מסלול ג: אתר או שרת משלך

התוצר הוא HTML סטטי רגיל, בלי שרת ובלי מסד נתונים. מה שצריך לשמור:

```
landing/index.html              ←  שורש הכתובת שבחרת
landing/thank-you/index.html    ←  אותה כתובת + /thank-you/
```

- **שרת או אחסון רגיל:** מעלים את תוכן התיקייה `landing` לתיקיית האתר (או לתת-תיקייה). חשוב שהתיקייה `thank-you` תישאר תיקייה עם `index.html` בתוכה, כדי ש-`/thank-you/` יעבוד.
- **וורדפרס:** עמוד חדש ← בלוק "HTML מותאם אישית" ← מדביקים את כל תוכן `index.html`, ובוחרים תבנית ריקה (Blank / Canvas). דף התודה הוא עמוד נפרד באותה שיטה, ומעדכנים בקובץ את הכתובת שאליה הטופס מפנה.
- **פלטפורמות שחוסמות HTML מלא (למשל Wix):** לא נלחמים בהן. מעלים ב-Netlify ומקשרים מהאתר.

פריסה על Cloudflare Pages ועל פלטפורמות אחרות: `reference/advanced.md` §5.

## 5. הבדיקות על הכתובת החיה

אחרי העלאה מוצלחת פותחים את הכתובת החיה (`open` / `start`), ועוברים על הצ'קליסט של `reference/copy-blocks.md` §14 **מול הכתובת החיה, לא מול הקובץ במחשב**. מדווחים עבר או נכשל שורה-שורה. חמש השורות שאסור לוותר עליהן:

| # | הבדיקה | איך בודקים |
|---|---|---|
| 1 | אפס `{{` בדף | מציגים מקור (Ctrl/Cmd+U) ומחפשים `{{`. יש? חסר ערך בקונפיג, ממלאים ומרנדרים ומעלים שוב |
| 2 | הכפתור עובד | לוחצים עליו באמת. במצב טופס: נשלח והגיע לדף התודה. במצב כפתור: נפתחה קבוצת הוואטסאפ |
| 3 | הטופס או הכפתור מצביעים למקום אמיתי | במצב Netlify Forms: שליחת בדיקה חוזרת בפקודה `--submissions`. במצב Google Form: הגיעה כשורה לגיליון, ואז מוחקים אותה. במצב כפתור: לינק הקבוצה פותח את הקבוצה הנכונה |
| 4 | תיבת ההסכמה עם לינק פרטיות | הלינק נלחץ ונפתח. אין מדיניות פרטיות? אומרים במפורש: **לא מפרסמים דף עם טופס בלי מדיניות פרטיות** |
| 5 | דף התודה נגיש | פותחים ידנית `<כתובת>/thank-you/` ורואים שהוא נטען |

בנוסף, מהנייד: כותרת עד 3 שורות, בלי גלילה אופקית, הכפתור הדביק מופיע אחרי גלילה.

בדיקה שנכשלה = מתקנים, מרנדרים ומעלים שוב באותה פקודה. לא מדווחים "עבר" על שורה שלא נבדקה בפועל.

## 6. איפה הלידים נשמרים

**זו שורה שנאמרת תמיד**, גם כששלב 9 נדחה וגם כשההעלאה נכשלה. סוגרים איתה את השלב ואת הסיכום הסופי, לפי מה שנבחר בשלב 3:

- **מצב Netlify Forms (ברירת המחדל, `lead_mode: netlify-forms`):** הנרשמים/ות נשמרים באתר עצמו. לראות אותם: `deploy_netlify.py --config ... --submissions` (או בדשבורד: Netlify ← האתר ← Forms). כל שורה: מתי, שם, טלפון, מייל, ההסכמה המלאה, ה-`utm_*` וגם כתובת IP ודפדפן. **חסרה שורה?** Netlify מסמנת לפעמים הרשמה תקינה כספאם, והיא לא מופיעה ברשימה הרגילה ובלי שום התראה: `--submissions --spam`. **תקרה:** בתוכנית החינמית החדשה אין הגבלה על מספר ההרשמות; בתוכנית החינמית הישנה יש 100 הרשמות לאתר לחודש, וחריגה משדרגת אוטומטית לחבילה בתשלום. וובינר יכול לעבור 100 נרשמים, אז אומרים את זה מראש.
- **מצב Google Form (`lead_mode: google-sheet`):** הנרשמים נוחתים בגיליון Google שמאחורי הטופס. לפתוח אותו: drive.google.com ← הגיליון בשם "<שם הפרויקט> תשובות", או מתוך עורך הטופס בלשונית "תשובות" ← אייקון Sheets. כל שורה: חותמת זמן, שם, טלפון, מייל, הסכמה.
- **מצב כפתור (`lead_mode: whatsapp-group`):** אין גיליון. הקבוצה **היא** הרשימה, ומספר החברים בה הוא מספר הנרשמים. אין כתובות מייל, ולכן אין תזכורות במייל.
- **מערכת דיוור מחוברת (`lead_mode: mailing-system`, המסלול המתקדם):** הלידים נוחתים ברשימה במערכת שחוברה, ואומרים את שם הרשימה במקום את הגיליון.

**שלב 9 נדחה?** אומרים את אותה שורה בזמן עתיד: "כשהדף יעלה לאוויר, הנרשמים/ות ייאספו באתר עצמו ואפשר יהיה למשוך אותם בפקודה אחת" (או לגיליון, או לקבוצה, או לרשימה). לא מסיימים סיכום בלי המשפט הזה.

## 7. דומיין משלך

יש דומיין (או תת-דומיין כמו `live.example.co.il`)? ב-Netlify: **Domain management** ← **Add a domain** ← מקלידים את הדומיין ← Netlify מציג רשומת DNS אחת (CNAME לתת-דומיין, או שרתי שמות לדומיין מלא). מוסיפים אותה אצל מי שמנהל/ת את הדומיין (הרשם או Cloudflare), ממתינים עד שהוא מסומן כתקין, ותעודת ה-SSL נוצרת לבד. אחר כך מרנדרים ומעלים שוב, כדי ש-`page_url` בקונפיג ובדפים יהיה הדומיין החדש. אין דומיין? הכתובת של Netlify עובדת מצוין ואפשר לחבר דומיין גם אחרי הוובינר.

## 8. עדכון הדף אחרי שינוי

שורה אחת, וזה כל הסיפור: משנים את ה-JSON, מרנדרים (`render_pages.py --only pages`), ומריצים בדיוק את אותה פקודת העלאה. הכתובת לא משתנה, כי `config.netlify_site_id` כבר בקונפיג.

## 9. תקלות נפוצות

| מה קורה | למה | מה עושים |
|---|---|---|
| הטוקן נדחה (401 או 403) | הועתק חלקית, או בוטל | יוצרים טוקן חדש ומעתיקים את כולו. הסקריפט אומר את זה בעברית |
| השם תפוס (422) | מישהו אחר ב-Netlify כבר לקח את השם | מריצים שוב עם `--site-name` ושם אחר (אותיות קטנות, מספרים ומקפים) |
| אין תשובה מהרשת | אינטרנט או חומת אש בעבודה | מנסים מרשת אחרת, או עולים במסלול ב |
| האתר לא נמצא (404) | האתר נמחק ב-Netlify, והמזהה בקונפיג מצביע לכלום | מוחקים את `netlify_site_id` מהקונפיג ומריצים שוב; ייווצר אתר חדש |
| הדף עלה אבל `/thank-you/` נותן 404 | הועלה רק `index.html` ולא כל התיקייה | מעלים את **כל** התיקייה `landing` |
| הכתובת החיה לא מופיעה בתוך הדף | הרינדור החוזר לא רץ | מרנדרים `--only pages` ומריצים את ההעלאה שוב |
| השליחה מהטופס מחזירה 404, והדף אומר "משהו השתבש" | זיהוי הטפסים כבוי באתר (ברירת המחדל של אתר חדש, או אתר שנוצר ב-Netlify Drop) | מריצים שוב את ההעלאה (היא מדליקה ומעלה שוב), או בדשבורד: Site configuration ← Forms ← Enable form detection ואז מעלים שוב |
| נרשם/ת אומר/ת שנרשם/ה, והשורה לא ברשימה | Netlify סימנה את ההרשמה כספאם, בלי התראה | `deploy_netlify.py --config ... --submissions --spam` |


## 2. מתכון הטוקן, מילה במילה

**מסלול א, קצר ככל האפשר:** app.netlify.com → הרשמה חינם → תמונת הפרופיל → **User settings** → **Applications** → בקטע Personal access tokens → **New access token** → שם → **Generate token** → מעתיקים (מוצג פעם אחת). מדביקים בצ'אט, ואומרים בשורה אחת יבשה: "נשמר ל-.env". ואז מריצים: `python3 <skill-dir>/scripts/deploy_netlify.py --config outputs/webinars/<slug>/config.json --token <הטוקן> [--site-name <slug>]`. הסקריפט יוצר את האתר אם אין `netlify_site_id`, מדליק עליו זיהוי טפסים, אורז את `landing` בזיכרון, מעלה, מחכה ל-`ready`, כותב `page_url` + `netlify_site_id` לקונפיג, מרנדר שוב את הדפים כדי שהכתובת החיה תיכנס אליהם, ומדפיס את הכתובת, את כתובת דף התודה ואת פקודת הנרשמים/ות. שגיאות מוסברות בעברית (טוקן שגוי, שם תפוס, אין רשת). הטוקן נשמר ל-`.env` בלבד, לא לקונפיג, ולא מודפס חזרה בצ'אט. **בלי אזהרות אבטחה ובלי להציע להחליף טוקן.** מסלול ב ומסלול ג: `publish.md` §3 ו-§4.
